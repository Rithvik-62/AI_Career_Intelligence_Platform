NOTEBOOK 2: 02_preprocessing.ipynb
Phase 2 — NLP Text Preprocessing
================================================================================

PURPOSE OF THIS NOTEBOOK:
Machine Learning models can't work with raw messy text. They need clean,
standardized, mathematical representations of text. This notebook cleans all
2091 resume texts using NLP (Natural Language Processing) techniques.

WHY DO WE NEED TEXT CLEANING?
Raw resume text contains:
  - URLs: "https://github.com/user/project" → not useful for career prediction
  - Email addresses: "john@email.com" → not useful
  - Special characters: "@#$%^&*" → noisy data
  - Numbers: "2020", "3.5 GPA" → usually not meaningful for classification
  - Stop words: "the", "a", "is", "was", "and" → appear in ALL resumes equally
  - Different forms: "worked" vs "working" vs "works" → same base word

After cleaning, only meaningful career-specific words remain.

CELL 3: THE clean_text() FUNCTION — HEART OF PREPROCESSING
--------------------------------------------------------------------------------
CODE:
    def clean_text(text: str) -> str:
        if not isinstance(text, str):
            return ""
        
        # 1. Convert text to lowercase
        text = text.lower()
        
        # 2. Remove URLs
        text = re.sub(r'http\S+|www\.\S+', '', text)
        
        # 3. Remove email addresses
        text = re.sub(r'\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b', '', text)
        
        # 4. Remove numbers
        text = re.sub(r'\d+', '', text)
        
        # 5. Remove punctuation and special characters
        text = re.sub(r'[^\w\s]', ' ', text)
        
        # 6. Remove extra spaces
        text = re.sub(r'\s+', ' ', text).strip()
        
        # 7. Remove stopwords & 8. Lemmatize words
        lemmatizer = WordNetLemmatizer()
        stop_words = set(stopwords.words('english'))
        words = text.split()
        cleaned_words = [
            lemmatizer.lemmatize(word) for word in words 
            if word not in stop_words
        ]
        
        return ' '.join(cleaned_words)

LINE BY LINE EXPLANATION:

    def clean_text(text: str) -> str:
    → Defines a function named clean_text.
    → "text: str" means it accepts a string input.
    → "-> str" means it returns a string output.
    → The ": str" and "-> str" are type hints — not enforced, just documentation.

    if not isinstance(text, str):
        return ""
    → Safety check: if the input is NOT a string (e.g., NaN, None, float),
      return an empty string instead of crashing.
    → isinstance(text, str) checks if text is a string data type.

    text = text.lower()
    → Converts ALL characters to lowercase.
    → "Python" → "python", "MACHINE LEARNING" → "machine learning"
    → WHY: ML treats "Python" and "python" as different words without this.
      Lowercase ensures they're treated as the same word.

    text = re.sub(r'http\S+|www\.\S+', '', text)
    → re.sub() = Regular Expression Substitution (find and replace).
    → r'http\S+|www\.\S+' is a regex pattern meaning:
        http followed by any non-space characters (\S+)
        OR www. followed by any non-space characters
    → Replaces matched URLs with '' (empty string = delete them).
    → Example: "visit https://github.com/user" → "visit "
    → WHY: URLs are unique to each person and don't indicate career roles.

    text = re.sub(r'\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,}\b', '', text)
    → This regex pattern matches email addresses.
    → \b = word boundary (start/end of a word)
    → [A-Za-z0-9._%+-]+ = letters, numbers, dots, underscores, plus, dash
    → @ = literal @ symbol
    → [A-Za-z0-9.-]+ = domain name characters
    → \. = literal dot
    → [A-Z|a-z]{2,} = at least 2 letters (like com, org, in, uk)
    → Example: "john.doe@gmail.com" → removed
    → WHY: Emails are personal identifiers, not career indicators.

    text = re.sub(r'\d+', '', text)
    → \d+ matches one or more digit characters (0-9).
    → Removes all numbers from the text.
    → Example: "Python 3.9" → "Python .", "2021-2023" → "-"
    → WHY: Years, version numbers, GPA values are usually not predictive
      of career role and add noise to the model.

    text = re.sub(r'[^\w\s]', ' ', text)
    → [^\w\s] means "any character that is NOT a word character (\w) or space (\s)"
    → \w = letters, digits, underscore. \s = whitespace.
    → So this removes: . , ! @ # $ % ^ & * ( ) - + = { } [ ] | \ / ? < >
    → Replaces them with a space ' '
    → Example: "C++, Java, MySQL!" → "C   Java  MySQL "
    → WHY: Punctuation doesn't help the model distinguish career roles.

    text = re.sub(r'\s+', ' ', text).strip()
    → \s+ matches one or more whitespace characters (spaces, tabs, newlines).
    → Replaces multiple spaces with a single space.
    → .strip() removes leading/trailing spaces.
    → Example: "python   machine  learning  " → "python machine learning"
    → WHY: After removing URLs, emails, numbers, punctuation — many extra
      spaces are left. This collapses them into clean single spaces.

    lemmatizer = WordNetLemmatizer()
    → Creates an instance of the WordNet Lemmatizer tool.

    stop_words = set(stopwords.words('english'))
    → Gets the list of 179 common English stop words.
    → Converts to a set() for O(1) fast lookup speed.
    → Examples in this list: "the", "a", "is", "was", "are", "be", "have",
      "it", "its", "we", "our", "not", "do", "as", "at", "this", "by"

    words = text.split()
    → Splits the cleaned text into a list of individual words.
    → "python machine learning sql" → ["python", "machine", "learning", "sql"]

    cleaned_words = [
        lemmatizer.lemmatize(word) for word in words 
        if word not in stop_words
    ]
    → This is a LIST COMPREHENSION — a compact loop.
    → For each word in words:
        IF the word is NOT a stop word:
            Lemmatize it (convert to base form)
            Add it to cleaned_words list
    → lemmatizer.lemmatize("running") → "running" (already base form for noun)
    → lemmatizer.lemmatize("models") → "model"
    → lemmatizer.lemmatize("worked") → "worked" (default assumes noun)
    → Note: lemmatizer works best with Part-of-Speech hints, but even without
      them it helps reduce vocabulary size.

    return ' '.join(cleaned_words)
    → .join() combines the list of words back into a single string.
    → ["python", "machine", "learning", "sql"] → "python machine learning sql"

COMPLETE EXAMPLE:
    INPUT:  "Developed ML models using Python 3.9 @ Google. Contact: john@google.com"
    Step 1 lowercase: "developed ml models using python 3.9 @ google. contact: john@google.com"
    Step 2 remove URL: same (no http/www)
    Step 3 remove email: "developed ml models using python 3.9 @ google. contact: "
    Step 4 remove numbers: "developed ml models using python . @ google. contact: "
    Step 5 remove punctuation: "developed ml models using python   google  contact  "
    Step 6 remove extra spaces: "developed ml models using python google contact"
    Step 7+8 remove stop words, lemmatize:
      "developed" → not stop word → lemmatize → "developed" ✓
      "ml" → not stop word → "ml" ✓
      "models" → not stop word → "model" ✓
      "using" → stop word? NO → "using" ✓
      "python" → not stop word → "python" ✓
      "google" → not stop word → "google" ✓
      "contact" → not stop word → "contact" ✓
    OUTPUT: "developed ml model using python google contact"

NOTEBOOK 4: 04_feature_engineering.ipynb
Phase 4 — Feature Engineering and Data Preparation
================================================================================

PURPOSE OF THIS NOTEBOOK:
Machine Learning algorithms ONLY understand numbers. They cannot process text
directly. This notebook converts our cleaned text into numerical feature vectors
using TF-IDF, and converts career role names into numbers using Label Encoding.

WHY TF-IDF?
TF-IDF (Term Frequency × Inverse Document Frequency) is the most popular
technique for converting text to numbers for classification. It creates a score
for each word in each document:
  - TF (Term Frequency) = how often a word appears in THIS resume
  - IDF (Inverse Document Frequency) = penalty for words appearing in MANY resumes
  - TF-IDF = TF × IDF → high score for words unique to specific roles

SIMPLE EXAMPLE:
If "tensorflow" appears 5 times in a Data Science resume but rarely in other
resumes → HIGH TF-IDF score (important, discriminative)
If "experience" appears 3 times in every single resume → LOW TF-IDF score (not useful)

    → Only keep the TOP 5000 most important word/phrase features.
    → Without this limit, we'd have tens of thousands of features — too slow.
    → Curse of dimensionality: too many features slows training and reduces accuracy.

    ngram_range=(1, 2)
    → Unigrams (1 word): "python", "machine", "learning", "sql"
    → Bigrams (2 consecutive words): "machine learning", "deep learning", "neural network"
    → Bigrams are crucial because "machine" alone doesn't tell much, but
      "machine learning" is a specific technology that predicts Data Scientist.

    min_df=2
    → Minimum Document Frequency = 2.
    → Ignores words that appear in FEWER than 2 resumes.
    → Single-document words are likely typos or very rare terms that won't help.

    max_df=0.95
    → Maximum Document Frequency = 95%.
    → Ignores words that appear in MORE than 95% of resumes.
    → Such words appear in almost all resumes → they're not discriminative.
    → Example: "professional", "experienced" appear in almost all resumes.

    stop_words='english'
    → Built-in English stop word removal as a second layer of cleaning.
    → Removes "the", "a", "is", etc. even if they somehow survived preprocessing.

    vectorizer.fit_transform(X)
    → FIT: Learns the vocabulary — which 5000 words/bigrams to track.
    → TRANSFORM: Converts each resume into a 5000-dimensional numerical vector.
    → Each number in the vector is the TF-IDF score for that word in that resume.
    → Returns a SPARSE MATRIX (most values are 0, only non-zero values stored).

    X_tfidf.shape
    → Returns (number_of_resumes, number_of_features).
    → Example: (2091, 5000) = 2091 resumes × 5000 word features.

    vectorizer.get_feature_names_out()[:10]
    → Returns the first 10 feature names (word/bigram column names).

    joblib.dump(vectorizer, '../models/vectorizer.pkl')
    → SAVES the fitted vectorizer to disk.
    → WHY: When a new resume is uploaded to the web app, we must transform

CELL 6: FEATURE STATISTICS
--------------------------------------------------------------------------------
CODE:
    density = X_tfidf.nnz / (X_tfidf.shape[0] * X_tfidf.shape[1])
    sparsity = 1.0 - density

LINE BY LINE EXPLANATION:
    X_tfidf.nnz
    → nnz = Number of Non-Zero elements in the sparse matrix.
    → Most TF-IDF matrix values are 0 (word not in resume = 0 score).

    density = nnz / (rows × columns)
    → Fraction of cells that have non-zero values.
    → Typically very low — like 0.5% to 2% density.

    sparsity = 1 - density
    → Fraction of cells that ARE zero.
    → If density = 0.01, sparsity = 0.99 = 99% zeros.

WHY SPARSE MATRIX:
A dense 2091×5000 matrix would use 2091 × 5000 × 8 bytes = ~80MB RAM.
A sparse matrix stores only non-zero values → much less memory → much faster.
scikit-learn automatically handles sparse matrices efficiently.

    joblib.dump(dt_model, '../models/decision_tree_model.pkl')

LINE BY LINE EXPLANATION:
    time.time()
    → Returns current time as a floating point number (Unix timestamp).
    → dt_time = time.time() - start_time = elapsed training time in seconds.

    DecisionTreeClassifier(random_state=42, criterion='gini', max_depth=None)
    → Creates a Decision Tree model object with these settings:

    random_state=42
    → Sets random seed for reproducible tree structure.
    → Decision Trees have random elements in how they break ties.

    criterion='gini'
    → GINI IMPURITY — the measure used to decide how to split nodes.
    → At each decision node, the algorithm tries every possible split
      and picks the one with the lowest Gini Impurity.
    → Gini Impurity = 1 - Σ(probability of class i)²
    → Gini = 0 means perfectly pure node (all same class).
    → Gini = 0.5 means maximally impure (equal mix of classes).
    → Alternative is 'entropy' — similar but uses logarithms.

    max_depth=None
    → No limit on how deep the tree can grow.
    → Without a limit, the Decision Tree can grow until every leaf has
      exactly 1 sample — this causes OVERFITTING on training data.
    → We don't set max_depth here to allow maximum training accuracy.
      Notebook 06 will show if it overfits.

    dt_model.fit(X_train, y_train)
    → FIT = TRAIN. This is the actual learning step.
    → X_train: the TF-IDF matrix (5000 features × 1672 resumes)
    → y_train: the role labels (1672 integers)
    → The Decision Tree algorithm:
        1. Finds the best word to split on first (e.g., "tensorflow")
        2. Creates two branches: has_tensorflow vs not_has_tensorflow
        3. Recursively finds best next split in each branch
        4. Continues until pure leaves or max_depth reached

    dt_model.classes_.shape[0]
    → After training, .classes_ holds the unique class numbers found.
    → .shape[0] = how many unique classes = 11 career roles.

OUTPUT YOU WILL SEE:
    Training Decision Tree...
    Training completed successfully in 0.8432 seconds.
    Number of classes learned: 11

WHY DECISION TREE IS FAST:
Decision Tree training is O(n × m × log n) where n = samples, m = features.
With 1672 samples × 5000 features, it's very fast on modern hardware.

LINE BY LINE EXPLANATION:
    KNeighborsClassifier(n_neighbors=5, weights='uniform', metric='minkowski')

    n_neighbors=5
    → When predicting for a new resume, find the 5 most similar resumes in training.
    → Votes among those 5 — whichever role is most common = prediction.
    → If 3 are "Data Scientist" and 2 are "ML Engineer" → predict "Data Scientist"

    weights='uniform'
    → Each of the 5 neighbors gets equal voting power.
    → Alternative: weights='distance' — closer neighbors get more influence.

    metric='minkowski'
    → Minkowski distance with default p=2 = Euclidean Distance.
    → Measures how "far" two TF-IDF vectors are in 5000-dimensional space.
    → Euclidean distance between two vectors: √(Σ(a_i - b_i)²)

    knn_model.fit(X_train, y_train)
    → KNN is a "lazy learner" — training just STORES the data.
    → No actual computation during training.
    → ALL computation happens at PREDICTION time (find 5 nearest neighbors).

WHY KNN IS SLOW AT PREDICTION:
For each new resume, KNN must compute distance to ALL 1672 training resumes.
1672 × 5000-dimensional distance calculations = slow for real-time use.
That's why KNN is typically not used in production for text classification.

LINE BY LINE EXPLANATION:

    preds = model.predict(X_test)
    → Runs the trained model on ALL 419 test resumes.
    → Returns 419 predicted class numbers.

    accuracy_score(y_test, preds)
    → Accuracy = Correct Predictions / Total Predictions × 100
    → If 415 out of 419 were correct → 415/419 = 0.9904 = 99.04%
    → This is the most intuitive metric — "what % did it get right?"

    precision_score(y_test, preds, average='weighted', zero_division=0)
    → For each career role, Precision = True Positives / (True Positives + False Positives)
    → "When the model says 'Data Scientist', how often is it actually right?"
    → If model said "Data Scientist" 40 times and 38 were actually Data Scientists:
      Precision = 38/40 = 0.95 = 95%
    → average='weighted': averages precision across all 11 classes, weighted by
      how many test samples each class has.
    → zero_division=0: prevents division-by-zero if a class has 0 predictions.

    recall_score(y_test, preds, average='weighted', zero_division=0)
    → For each career role, Recall = True Positives / (True Positives + False Negatives)
    → "Out of all ACTUAL Data Scientists, how many did the model correctly find?"
    → If there were 40 actual Data Scientists and model found 37:
      Recall = 37/40 = 0.925 = 92.5%
    → Also called Sensitivity or True Positive Rate.

    f1_score(y_test, preds, average='weighted', zero_division=0)
    → F1-Score = Harmonic Mean of Precision and Recall
    → F1 = 2 × (Precision × Recall) / (Precision + Recall)
    → F1 is useful when you want BOTH precision AND recall to be high.
    → F1 of 1.0 = perfect. F1 of 0.0 = completely wrong.
    → We use F1 as the PRIMARY selection criterion for the best model.

    classification_report(y_test, preds, target_names=class_names)
    → Prints a detailed table showing Precision, Recall, F1 for EVERY class.
    → Also shows "support" (number of test samples per class).

    cross_val_score(model, X_train, y_train, cv=5, scoring='accuracy', n_jobs=-1)
    → K-Fold Cross Validation with k=5 folds.
    → Splits training data into 5 equal parts.
    → Trains model 5 times, each time using 4 parts for training, 1 for validation.
    → Returns 5 accuracy scores.
    → cv_mean = average of those 5 scores = more reliable accuracy estimate.
    → n_jobs=-1 uses ALL available CPU cores for speed.

    WHY CROSS-VALIDATION?
    Single train-test split might be lucky or unlucky. Cross-validation gives
    the average performance across 5 different train-test combinations.
    A model with high CV score is reliably good, not just lucky once.

    confusion_matrix(y_test, preds)
    → Creates an 11×11 matrix (11 roles × 11 roles).
    → Row i, Column j = "How many actual Class-i resumes were predicted as Class-j?"
    → DIAGONAL values = correct predictions (actual=predicted).
    → OFF-DIAGONAL values = errors (confused one role for another).
    → A perfect model has all values on the diagonal and zeros elsewhere.

    sns.heatmap(cm, annot=True, fmt='d', cmap='Blues', ...)
    → annot=True: shows the count number inside each cell.
    → fmt='d': formats as integer (not decimal).
    → cmap='Blues': darker blue = larger number.
    → The diagonal (correct predictions) should appear darkest.

                   "MongoDB", "Git", "Docker", "TypeScript"]

    2. Gets CANDIDATE'S skills from parsed_data['skills'].
       Example: ["HTML", "CSS", "JavaScript", "MySQL", "Java", "Spring Boot"]

    3. MATCHING SKILLS = set(candidate_skills) ∩ set(required_skills)
       = ["HTML", "CSS", "JavaScript"] (intersection)

    4. MISSING SKILLS = set(required_skills) - set(candidate_skills)
       = ["React", "Node.js", "REST APIs", "MongoDB", "Docker", "TypeScript"]

    5. Coverage % = len(matching) / len(required) × 100
       = 3 / 10 × 100 = 30%

    6. PRIORITY RANKING: ranks missing skills by importance to the role.
       "React" = Critical (most important for Web Developer jobs)
       "Node.js" = Critical
       "REST APIs" = High
       "MongoDB" = High
       "Docker" = Medium

    7. LEARNING HOURS: estimated hours to learn each missing skill.
       Based on internal database of skill complexity.

    8. LEARNING ROADMAP: week-by-week plan covering all missing skills.

OUTPUT YOU WILL SEE:
    Predicted Career: Software Developer
    Career Readiness Score: 50% (Developing)

WHY "MATHEMATICAL MAPPING":
Set theory operations (intersection, difference) are the mathematics behind this:
  Matching = Candidate ∩ Required (intersection = common elements)
  Missing = Required - Candidate (difference = elements in Required but NOT in Candidate)
This is simple but powerful mathematics applied to career planning.
